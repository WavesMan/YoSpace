# 文章渐进阅读与滚动打字效果

日期：2026-10-19。

## 当前行为

文章改为首屏优先显示，后续内容随阅读位置渐进出现。标题、元信息与完整目录优先可用，正文段落进入视口后在 240～1000ms 内逐字揭示。向上回看不会重新播放；快速滑过的段落会直接完成，点击或聚焦段落也能立即显示全文。系统开启“减少动态效果”时直接呈现文字。

图表提前约 600px 预加载，只有接近阅读位置才导入 Mermaid 并生成 SVG。生成完成并进入视口后，以约 800ms 的逐行扫描配合渐显展开图形，避免完整 SVG 突然弹出。已经完成的图表保持挂载，滚离视口不会卸载。尚未生成时显示预留空间与可查看的源码；渲染失败后直接展开源码。

代码块服务端先输出可复制的纯文本，进入视口后在 240～1400ms 内逐字揭示。支持的代码语言接近视口时才下载高亮模块，打字过程中固定当前 DOM，完成后以 200ms 的轻微渐显切入高亮。两种状态共用行容器、行号、字体与长行换行规则，避免替换后代码框变高或变矮。纯文本、未知语言和图表源码使用相同打字效果与轻量展示。高亮模块失败时继续保留可阅读代码。

点击代码、复制按钮或操作图表控件时会立即结束对应揭示，保留完整复制和拖动缩放能力。减少动态效果与禁用脚本的阅读回退同样适用于代码和图形。

图片继续使用浏览器原生懒加载，并在解码完成、进入视口后执行与首页社交图标一致的左侧渐入：水平偏移 -16px、透明度 0 → 1，持续 0.8 秒，缓出。同屏图片最多按 80ms 间隔错峰 4 张，不继承首页从 600ms 开始的固定等待，也不累加整篇文章的延迟。图片加载失败时显示浏览器替代文字，缓存图片与不支持解码 API 的环境同样可以呈现；关闭预览或回看不会重播。减少动态效果、打印及禁用脚本时直接显示图片。

首屏就绪检查只等待正文数据与基础布局，不再等待图片、整篇文章的图表、屏外高亮或播放器模块。

## 实现方式

这是一种类似 LLM 输出的视觉揭示效果。现有文章仍以服务端 Markdown 内容为来源，没有新增 SSE 接口，也没有将静态文章拆成大量网络请求。

`StreamingText.tsx` 保留完整的段落 DOM，使用文字 `Range` 的字形位置配合 `clip-path` 逐字揭示。文字本身不会被逐字改写，也不为每个字符创建独立元素，因此不会因动画而重复解析 Markdown，段落高度始终保持不变。强调、行内代码与链接继续保留原有语义。中文、emoji 和组合字符通过 `Intl.Segmenter` 按字素处理；不支持时使用 Unicode 码点回退。

同一组件的 `code` 模式只遍历代码文本，忽略装饰性行号；`diagram` 模式将完整 SVG 按 16 个扫描行逐步揭示，不拆写 SVG 字符串。代码外壳与动画容器在高亮替换时保持挂载，避免重播动画。

正文段落和简单列表项使用此效果。含图片、嵌套列表、表格等块内容的段落或列表项直接呈现，避免裁切嵌套交互。读屏和复制读取完整文本，不逐字播报；打印与禁用 JavaScript 时关闭文字裁切。

`useViewportEntry.ts` 按预加载距离共用 `IntersectionObserver`，进入后取消观察。没有此 API 的环境直接启用内容作为兼容回退。`LazyCodeBlock.tsx` 复用同一个高亮模块 Promise，避免多个代码块重复下载。

首屏的 `PageReadiness` 保留正文请求错误、路由重置与超时重试机制。目录始终基于完整 Markdown 生成，未阅读章节的标题锚点也始终存在。滚动动画不改动文章结构，目录可以直接跳至后文。

## 性能观测

以下是第一版渐进正文的历史观测，尚未加入本轮代码行容器和图形扫描效果，DOM 与传输大小不能直接当作当前版本指标。同一篇长文 `/blog/automated-semver-version-tag-release-workflow`，包含 13 张 Mermaid 图表。本机 Edge Chromium、模拟 iPhone 13、中文、生产构建、无网络限速的一轮观测：

| 项目 | 上一版整页等待 | 当前渐进阅读 |
| --- | --- | --- |
| 首屏可读 | 约 1.0～1.5s | 一轮约 0.44s |
| 首屏时已渲染图表 | 13 | 0，屏外图表按需生成 |
| 首屏 DOM 节点 | 约 5655 | 约 2787 |
| 首屏阶段 JS `transferSize` 合计 | 约 2.28MB | 一轮约 2.08MB |

这些是本机观测值，包含共享组件与播放器资源，不能当作线上分位数或某一个依赖的大小。首屏可读和整篇所有图表完成是两种不同指标，当前优化优先缩短前者。真机 Safari 的速度仍需要单独验证。

同一套限速参数下，当前模式一轮移动端约 3.6s 开始阅读，前一版等待全部图表约 6.45s。当前首次可读时屏外图表尚未开始生成，之后按滚动位置单独完成。

图表加载后尺寸仍可能与占位空间不同。预留最小高度并提前加载能减轻变化，但不等同于所有图表零布局偏移；若需更严格地固定空间，可在内容构建阶段预计算每个图表的尺寸或 SVG。

## 验证与复测

单元测试覆盖完整服务端文本、视口外不启动图表、进入后只加载一次、段落与代码按视口揭示、图形扫描、立即完成、减少动态效果、代码空行与长命令一致性、高亮不打断动画、嵌套内容不裁切，以及原有主题切换和图表触屏操作。

`scripts/check-page-loading.cjs` 已改为检验渐进阅读：首屏留有未加载的图表，滑至后文会生成对应图表并揭示文字，向上回看不重播动画，段落高度不变，同时验证返回文章、英文浏览器偏好、暗色模式和无 JavaScript 阅读。

此前另在个人博客的 `/blog/wsl2-ubuntu-secondary-environment-setup-migrate-disk` 页面验证了移动与桌面代码打字效果、高亮前后框体高度、复制全文和减少动态效果。提交至 YoSpace 主仓的回归脚本改为生成独立的临时 Markdown 样本，覆盖 13 张图表、长命令和无语言标记代码，结束时清理样本，不依赖个人博客文章。截图目录还会保存 `progressive-code.png` 与 `progressive-diagram.png` 以便视觉检查。

运行前需安装或指定已有的 Playwright，并提供 Edge 浏览器，也可通过 `PLAYWRIGHT_BROWSER` 指定 Chrome 等已安装的 Chromium 渠道。环境变量 `PLAYWRIGHT_MODULE` 可指向本机模块路径；先构建项目，再以 `PRODUCTION=1` 运行脚本即可临时启动 3001 端口进行生产模式回归，结束后自动关闭测试服务器。`SLOW=1` 启用 CPU 降速 4 倍、100ms 延迟、750000 B/s 下载限速；`SCREENSHOT_DIR` 可保存移动端效果截图。脚本仅适用于本机仓库的开发或生产服务器，会临时写入当前工作区的文章目录。

## 图片加载与响应式布局回归

图片动效参考首页 `Profile.module.css` 的 `profileSocialFadeInRight`：保留左移 16px、0.8 秒缓出的节奏，同时按文章阅读位置决定开始时间。图片解码、视口进入、失败和完成状态由 `PostImage.tsx` 统一处理，不影响大图预览的缩放与拖动。

目录使用视口动态高度与安全区约束整个容器，浮动模式将开关按钮和间距计入可用空间。面板与滚动子项设置 `min-height: 0`，标题和按钮保持固定尺寸，长目录只在正文区域滚动。桌面侧栏遵循同样的约束，横屏或低高度窗口也能收缩。

Archive 卡片宽度基于父容器计算，时间线采用对称内边距，装饰线脱离尺寸计算；卡片信息行允许换行，窄屏下缩小内边距，避免日期与阅读链接撑宽卡片。

`scripts/check-responsive-layout.cjs` 会创建临时图片与 80 个长标题的文章样本，覆盖 1440×900、1440×320、1024×600、771×1340、390×844、320×568、844×390 七组尺寸及明暗主题，验证目录不越过屏幕、长目录内部可滚动、归档左右留白一致、图片解码与动画衔接、预览后不重播，以及减少动态效果与禁用脚本的图片回退。调用参数与上面的脚本相同；生产模式使用临时 3002 端口，`SCREENSHOT_DIR` 可保存 Archive 的明暗主题截图。样本与测试服务器在结束时清理。
