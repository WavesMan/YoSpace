# 主题优先级与验证

默认跟随系统；用户手动选择亮色或暗色后，优先采用该选择。导航提供“跟随系统主题”入口，可恢复自动模式。偏好记录在 `localStorage` 的 `theme-preference` 中，值为 `system`、`light` 或 `dark`。

旧实现把首次检测到的系统主题和手动选择一起写入 `theme`，使自动检测逐渐变成固定主题，且没有监听系统变化。旧值无法区分来源，因此新实现忽略旧键；升级后默认恢复跟随系统，用户可重新手动选择。

首屏脚本在 `head` 应用主题；客户端订阅系统变化、页面恢复和跨标签存储变化。自动同步不保存固定偏好，也不会用服务器亮色快照覆盖已应用的暗色。禁止存储时仍按系统显示，手动操作在当前页面的内存中生效。

浏览器回归另发现播放器的音量快照直接读取存储，会在存储被禁止时触发整页错误回退，使已经设置的主题也消失。播放器的音量、索引和进度改用现有的容错存储工具，存储不可用时继续保留内存状态。

验证包括五项主题单元测试，以及生产模式浏览器的旧键迁移、系统实时切换、手动偏好刷新保持、恢复跟随系统和存储 getter 抛出 `SecurityError` 的完整页面检查。测试入口：`npm run test -- --run src/utils/theme.test.ts`。
